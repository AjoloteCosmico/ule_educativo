Identidad Gráfica — Sitio del Juego de Pelota Mesoamericano

1. Brief de marca

Sitio educativo dedicado a difundir la práctica y el conocimiento del juego de pelota mesoamericano en todas sus variantes (cadera, mazo, antebrazo), cubriendo dos vertientes:

  • Histórica: desde los olmecas hasta el periodo posclásico.
  • Contemporánea: asociaciones, reglamentos y práctica actual del deporte.

El diseño debe verse amigable, agradable a la vista y llamativo, pero siempre priorizando la lectura del texto. Debe conservar cierta seriedad: un sitio educativo agradable, no una red social. La estética debe invitar a explorar el contenido.

Referencia visual/textural: evocar textura de piedra (superficies, fondos o detalles decorativos con esa sensación material, sin perder legibilidad).

2. Voz y tono

  • Educativo ligero: no somos "la academia" (no acartonado, no jerga excesiva), pero tampoco una red social (no informal en exceso, no clickbait).
  • Nos dirigimos siempre en segunda persona ("tú").
  • No afirmamos verdades absolutas ni tomamos postura fija en debates o temas políticos/controvertidos: documentamos y estamos abiertos a observaciones para mejorar la información.

El sitio se escribe en español como idioma principal. A futuro podrá tener versiones en inglés y francés.

3. Estructura del sitio

Home / index.html: hasta arriba, el icono principal (que funciona como logo) y debajo el nombre del sitio. Es el primer punto de contacto con la identidad.

Secciones principales:

  1. Índice: listado de todo el contenido. Debe incluir elementos destacados/llamativos que puedan actualizarse con el tiempo (ej. contenido reciente o curado).
  2. Artículo / Blog: texto plano, formato de lectura larga.
  3. Catálogos: pensados sobre todo para colecciones de imágenes (ej. piezas arqueológicas). Estructura:
    • Encabezado de colección: descripción general.
    • Grid dinámico (cuadrícula tipo flex/grid) de elementos, cuadrados medianos.
    • Cada card: imagen + título + badges de categoría (ej. periodo: preclásico/clásico/posclásico; cultura: golfo, olmeca, cacaxtla, etc.).
    • El mismo mecanismo de catálogo debe poder reutilizarse para distintos catálogos, cada uno con su propio lote de categorías (ver sección 6, componentes nativos).
  4. Recursos dinámicos: contenido interactivo (simulador de tiro parabólico actualmente; a futuro, minijuegos y otras herramientas interactivas).

4. Sistema de diseño (CSS)

Modos: claro y oscuro únicamente. Todo declarado como variables CSS en :root para poder modificarse o experimentar sin tocar el resto del código.

4.1 Color

:root {
  /* Base */
  --color-principal: #058A41;
  --color-secundario: #63372C;
  --color-fondo-claro: #fdfdff;
  --color-fondo-oscuro: #1E352F;
  --color-texto-claro: #282828;
  --color-texto-oscuro: #c3d4d0;

  /* Cards */
  --color-card-claro: #F5F1E9;          /* tono hueso / piedra clara */
  --color-card-oscuro: #2A2F2C;         /* gris muy oscuro con leve tinte verdoso */

  /* Texto sobre cards */
  --color-titulo-card: var(--color-principal);   /* títulos y resaltados */
  --color-cuerpo-card-claro: #2C2C2C;            /* contraste AA sobre hueso */
  --color-cuerpo-card-oscuro: #D0D8D5;           /* contraste AA sobre card oscuro */

  /* Links */
  --color-link: #058A41;
  --color-link-hover: #046B33;
  --color-link-visitado: #4A6B5A;
  --color-link-focus: #058A41;                   /* mismo color + outline visible */

  /* Badges – Periodo */
  --badge-preclasico: #8B5E3C;
  --badge-clasico: #2E6B4E;
  --badge-posclasico: #5C4033;

  /* Badges – Cultura (ejemplos fijos, ampliar según catálogo) */
  --badge-olmeca: #3D5A45;
  --badge-golfo: #6B4E31;
  --badge-cacaxtla: #4A6741;
  --badge-maya: #2F4F4F;
  --badge-azteca: #5C3317;
}

Notas de contraste:

  • Texto de cuerpo sobre cards cumple mínimo WCAG AA.
  • Títulos usan el verde principal para mantener identidad y jerarquía clara.
  • Los badges usan tonos terrosos/pétreos que evocan la referencia de piedra sin competir con el verde principal.

4.2 Tipografía

:root {
  --font-principal: "Ubuntu", sans-serif;
  --font-anotaciones: "Helvetica", sans-serif; /* uso en cursiva vía font-style: italic */
}

Pesos:

  • Títulos de sección (h1, h2): Ubuntu Bold (700)
  • Títulos de card / subtítulos (h3): Ubuntu Medium (500)
  • Cuerpo: Ubuntu Regular (400)
  • Anotaciones / notas al pie: Helvetica Italic (400 italic)

Escala tipográfica (mobile → desktop):

Line-height recomendado: 1.5 para cuerpo, 1.25 para títulos.

4.3 Bordes, espaciado y sombras

:root {
  /* Radios */
  --radius-sm: 0.375rem;   /* 6px – badges, botones pequeños */
  --radius-md: 0.75rem;    /* 12px – cards, inputs */
  --radius-lg: 1rem;       /* 16px – contenedores grandes */

  /* Espaciado */
  --space-xs: 0.25rem;
  --space-sm: 0.5rem;
  --space-md: 1rem;
  --space-lg: 1.5rem;
  --space-xl: 2.5rem;
  --space-2xl: 4rem;

  /* Sombras */
  --shadow-card-claro: 0 2px 8px rgba(0, 0, 0, 0.06);
  --shadow-card-oscuro: 0 2px 8px rgba(0, 0, 0, 0.25);
}

Los márgenes generales deben ser generosos para que el contenido “respire”. Preferir --space-lg y --space-xl entre secciones.

4.4 Responsive

Mobile first, obligatorio.

:root {
  --bp-sm: 480px;
  --bp-md: 768px;
  --bp-lg: 1024px;
  --bp-xl: 1280px;
}

Grid de catálogo (columnas):

  • < 480px → 1 columna
  • ≥ 480px → 2 columnas
  • ≥ 768px → 3 columnas
  • ≥ 1024px → 4 columnas

Gap del grid: var(--space-md) en mobile, var(--space-lg) en desktop.

4.5 Componentes

Cards de texto (artículo/blog):

  • Fondo: --color-card-claro / --color-card-oscuro
  • Título: --color-titulo-card + Ubuntu Medium
  • Cuerpo: variables de cuerpo según modo
  • Padding interno: var(--space-lg)
  • Borde redondeado: var(--radius-md)
  • Sombra: según modo

Badges:

  • Forma: píldora (border-radius: 999px)
  • Altura: ~1.5rem / padding horizontal 0.625rem
  • Texto: Ubuntu Regular, 0.75rem, mayúsculas, letter-spacing 0.02em
  • Sin icono interno por defecto (mantener minimalismo)
  • Color de fondo según categoría (variables de arriba); texto blanco o casi blanco para contraste

Cards de anuncio:

  • Imagen/banner proporción fija 4:5 vertical
  • Elementos: imagen + (contacto + slogan) + texto legal/condiciones
  • Prioridad visual fija:
    1. Imagen (más peso visual)
    2. Contacto + slogan (segundo nivel)
    3. Texto legal (más discreto, tamaño anotación)
  • Layout: columna en mobile; puede pasar a fila (imagen izquierda + contenido derecha) a partir de --bp-md si el contenedor lo permite. El orden de prioridad se mantiene.

Iconos:

  • Estilo: minimalistas, línea limpia o silueta sólida, sin detalles excesivos.
  • Color por defecto: blanco, siempre sobre el color principal (no dependen del modo).
  • Cuando no están sobre el color principal (badges, texto suelto, fondos claros): usar --color-secundario o un gris neutro oscuro (#3A3A3A) según contexto. Nunca usar el verde principal sobre fondos claros para evitar pérdida de contraste.
  • Set inicial:
    • Icono principal: cancha de pelota (logo + favicon)
    • Unidad de greca (para repetirse y formar líneas divisorias)
  • Se irán agregando más iconos con el tiempo. Mantener el mismo lenguaje visual (peso de trazo, nivel de detalle).

Tratamiento de fotografías (piezas arqueológicas y juego actual):

  • Color natural (sin duotono ni filtros pesados).
  • Ligera viñeta o borde sutil en tono piedra (--color-secundario al 15-20% de opacidad) para evocar materialidad sin distorsionar la imagen.
  • En modo oscuro: se mantiene el color natural; el contenedor de la card aporta el contraste.
  • Evitar overlays fuertes que reduzcan legibilidad del contenido.

5. Logo / Icono principal

  • No hay wordmark independiente: el icono de la cancha de pelota es el logo.
  • Uso en Home: icono arriba + nombre del sitio debajo (“ule educativo”), alineados al centro o a la izquierda según el layout.
  • Nombre definitivo del sitio: ule educativo.

Versiones del logo (máximo 3):

  1. Principal: icono + texto “ule educativo” debajo (uso en home y cabeceras).
  2. Icono solo: para favicon, botones, espacios reducidos.
  3. Monocromo: versión en blanco o en --color-secundario para fondos de color o impresión.

No se requieren más variantes.

Favicon (mínimo necesario):

  • 16×16 y 32×32 (PNG o ICO)
  • Apple Touch Icon 180×180 (PNG)
  • Formato de exportación preferido: PNG con fondo transparente + un .ico que agrupe 16/32.

Espacio de protección:

  • Mínimo equivalente a 1/4 de la altura del icono en todos los lados cuando se usa como logo.
  • No colocar texto ni otros elementos dentro de esa zona.

6. Nota sobre implementación de componentes

La intención es construir con componentes nativos de JS (Web Components) la mecánica y estilos de catálogo, de forma que se escriban una sola vez y se repliquen en distintos catálogos, cada uno con su propio lote de categorías/badges. Esto es una decisión de arquitectura de código — ver detalle en arquitectura.md, pero se anota aquí porque condiciona el diseño: los estilos de card, grid y badges deben poder parametrizarse (vía atributos/props) sin duplicar CSS.

Documento de identidad gráfica completo. Todos los huecos marcados originalmente como pendientes han sido definidos de forma coherente con el brief: legibilidad prioritaria, sensación de piedra, tono educativo amigable y sistema de variables CSS listo para implementar.
